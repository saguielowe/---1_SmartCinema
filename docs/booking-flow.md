# 购票与订单流程

这份文档用于统一“用户看到什么、管理员看到什么、假支付和锁票怎么处理”。

## 一、普通用户流程

1. 注册 / 登录
2. 选择电影、场次、影厅
3. 查看余票和座位图
4. 填写观影条件，生成推荐
5. 手动调整座位
6. 点击“预订”或“立即购票”
7. 在“我的订单”里查看、取消、退票

## 二、管理员流程

1. 管理员登录
2. 查看全部订单
3. 查看全部场次余票与座位状态
4. 查看热度统计
5. 必要时重置订单或座位状态

## 三、订单状态流转

### 用户预订

- 创建订单，状态为 `booked`
- `paymentStatus` 为 `pending`
- 座位状态改为 `reserved`

### 用户完成假支付

- 不接真实支付接口
- 可以做一个简单弹窗或支付页
- 点击确认后：
  - 订单状态改为 `purchased`
  - `paymentStatus` 改为 `paid`
  - 座位状态改为 `sold`

### 用户取消预订

- 订单状态改为 `cancelled`
- 座位恢复为 `available`

### 用户退票

- 已购票订单状态改为 `refunded`
- 座位恢复为 `available`

## 四、锁票机制建议

为了让流程更合理，建议实现一个轻量锁票机制：

- 用户点击预订后，系统为该订单写入 `expiresAt`
- 座位写入 `lockedUntil`
- 如果到期还没完成支付，则自动释放座位

说明：

- 这只是前端本地模拟，不是真实并发锁
- 对本次作业已经足够

## 五、需要提前对齐的点

- 普通用户不是只能看余票，还要有“我的订单”
- 管理员在普通用户能力之外，额外拥有管理能力
- 假支付是可接受的，但必须和订单状态、座位状态联动
- 锁票字段要提前写进数据结构，避免后面返工
