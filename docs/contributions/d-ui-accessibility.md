## 问题与处理

- 浏览器可能同时加载新版 `app.js` 和缓存中的旧版 `store.js`，导致“保存设置”调用不存在的接口后静默中断：统一升级静态资源版本号，并增加旧 Store 兼容保存路径和弹窗内错误提示。
- 大字体通用控件高度曾误伤开关，导致开关被拉成竖向胶囊；同时窄弹窗产生大量换行和内部整体滚动：为开关增加独立横向尺寸，大字体弹窗扩宽，并改为只有设置列表滚动、标题和操作按钮固定可见。
- 高对比度新增的 3px 边框曾改变开关内部坐标，使白色滑块向右下偏移；现改为所有模式预留同样的透明边框，并按内容区重新计算滑块位置，开启和关闭状态的上下边距保持对称。
- 设置列表曾永久预留滚动条槽位，导致设置卡片比标题和底部按钮向左缩进；现仅在实际溢出时占用滚动条宽度。浏览器缩放后顶部账号区的隐藏横向溢出也已通过 760px 平板断点消除。
- 账号、订单和座位逻辑已由 C/A 完成：D 只调用公开 Store 和 SeatMap 接口，不复制业务状态。
- Canvas 颜色不能被普通 CSS 覆盖：给 `createSeatMap()` 增加 `colorBlindFriendly / reduceMotion` 可选参数，默认值保持原行为。
- 管理员订单多时会无限拉长页面：保留 `store.getOrders()` 的权限过滤，在展示层增加状态筛选和分页。
- 移动端无法同时压缩 300 座影厅并保留可读座号：让 Canvas 在卡片内部横向滚动，页面主体仍无横向溢出。
