# 产品与需求导览

这个目录现在的作用是“快速上手”，不是最终规范来源。

如果你是第一次打开仓库，建议按下面顺序看：

1. [需求拆解](./需求拆解.md)
2. [任务分工建议](./任务分工建议.md)
3. [字段设计](../docs/data-schema.md)
4. [购票与订单流程](../docs/booking-flow.md)
5. [Git 协作约定](../docs/collaboration.md)

## 怎么理解这套结构

- `01_产品与需求`：给人快速读懂项目
- `docs/`：给协作开发对接口和流程
- `03_源码/`：已经预留了 A / B / C / D 对应的代码落脚点

## 当前最重要的共识

- 页面整体 UI 和最终整合不等于 Canvas 组件本身
- 普通用户也有订单中心，不只是管理员
- 数据存储走 LocalStorage / 本地 JSON，不使用数据库
- 支付采用假支付，配合锁票状态演示即可
