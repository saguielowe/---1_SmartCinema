## 一、必须覆盖的内容

### 核心主链路

- 登录 / 注册
- 电影与场次选择
- 智能推荐
- 手动选座
- 订单中心

### 六大功能模块

- 智能推荐选座
- 手动选座
- 影院热度地图
- 观影体验评分
- 无障碍模式
- 订单中心

### 明确的技术要求

- 必须使用 Canvas 绘制影厅
- 不使用第三方图表库
- 使用 HTML5、CSS3、JavaScript
- 数据存储使用 LocalStorage 或本地 JSON
- 支持 PC / 平板 / 手机

## 二、当前已经定下来的实现口径

### 1. 登录注册

- 先做简化版 `username + password`
- 角色区分为 `user | admin`
- 不做复杂认证、不做邮箱验证

### 2. 用户与管理员

普通用户：

- 选电影和场次
- 看余票
- 推荐 / 手动选座
- 预订 / 假支付 / 退票
- 查看“我的订单”

管理员：

- 查看全部订单
- 查看全部场次余票与座位状态
- 查看热度统计
- 必要时调整订单或座位状态

### 3. 支付与锁票

- 不接真实支付接口
- 做假支付确认弹窗或页面
- 预订后先锁票
- 超时未支付则自动释放座位

### 4. 座位建模

- 不是简单整齐矩阵
- 使用 `pattern + offsetX + curveDepth` 描述影厅
- 支持过道、空缺、不规则排布和弧形布局

## 三、推荐的开发顺序

1. 电影 / 场次 / 用户基础数据
2. 影厅数据结构与 Canvas 座位图
3. 推荐规则与选座交互
4. 订单中心与 LocalStorage
5. 热度地图、评分、无障碍模式
6. 说明文档与 AI 使用记录

## 四、加分项取舍建议

优先考虑：

- AI 顾问式推荐交互
- 拖拽选座
- 动画优化
- 个性化影厅布局

谨慎考虑：

- WebSocket 实时座位更新

原因：

- 会把项目拖成前后端联调
- 当前作业性价比不高

## 五、最低可提交版本

如果时间紧，至少保证：

- 登录注册可用
- 场次和影厅数据完整
- Canvas 座位图能交互
- 推荐规则能跑
- 订单中心能演示
- 报告能说明设计过程和 AI 使用情况
